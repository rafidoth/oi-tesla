## Key Decisions

| # | Decision | Choice |
|---|---|---|
| ORM | Drizzle (SQL-first, TS-native) | Schema as TS files in `db/schema/`; migrations via Drizzle Kit |
| Repository placement | Hybrid | Domain repos live inside their module; `db/` holds only client + schema |
| Module slicing | Domain-action | `auth`, `users`, `locations`, `rides`, `pools`, `driver`, `payments`, `events` |
| Service pattern | Class with constructor injection | `class RideService { constructor(private repo: RideRepository) {} }` |
| Pool complexity | Single service, composed internally | `PoolService` delegates to `MatchingEngine`, `SeatGuard`, `PoolStateMachine` |
| DI wiring | `*.module.ts` per feature | Each module wires its own deps and exports the Express Router |
| Validation | Shared `validate(schema)` middleware | Zod `safeParse` at the HTTP boundary; business rules stay in the service |
| Domain objects | Hybrid OO | `Pool`, `Ride` → domain classes with methods; `FareCalculator` → class with config; matching → pure functions |
| Tests | `server/tests/<domain>/` | Unit tests only; organised by domain name; no co-location |
| Cross-cutting | `shared/` only | `lib/` removed; `shared/` holds errors, middleware, utils, types, third-party wrappers |

## Layer Rules (Unidirectional — No Upward Calls)

```
Routes → Controller → Service → Repository → db/client
                  ↘            ↘
               Domain Objects   shared/
```

- **Routes** — declare endpoints, apply middleware, call the controller. Zero logic.
- **Controllers** — parse the validated request, call the service, shape the HTTP response. No business rules.
- **Services** — orchestrate domain objects and repositories. Own all invariants and state transitions. Never touch `req`/`res`.
- **Repositories** — Drizzle queries only. Return plain data (row types). No business logic.
- **Domain objects** — encode identity, state, and behaviour. No I/O; no framework imports.
- **`shared/`** — pure infrastructure (errors, middleware, utils, wrappers). No domain imports.
- **`db/`** — Drizzle client singleton + schema definitions. No imports from `modules/` or `shared/middleware`.

## Domain Object Design Reference

### When to use a class

| Concept | Type | Reason |
|---|---|---|
| `Pool` | Domain class | Has identity (id), mutable state (status, occupiedSeats), behaviour (`canJoin()`, `canAccept()`) |
| `Ride` | Domain class | Has identity, derived status, and a cancel guard that encodes a business rule |
| `FareCalculator` | Class with config | Owns base fare + perKm strategy; injected with env config at startup |
| `MatchingEngine` | Stateless class or pure functions | No identity, no mutable state — seeded route data is read-only |
| `SeatGuard` | Class | Wraps the atomic DB update; the "object" here is the transaction boundary |
| `PoolStateMachine` | Pure functions + transition table | Deterministic — same inputs always give same output; easy to unit-test in isolation |
| `EventsService` | Class | Has a dependency (repo); write funnel with logging side-effect |

### Domain Object example shapes

```ts
// pools/domain/Pool.ts
export class Pool {
  constructor(private readonly data: PoolRow) {}

  get id() { return this.data.id; }
  get status() { return this.data.status; }
  get occupiedSeats() { return this.data.occupiedSeats; }
  get capacity() { return this.data.capacity; }

  canJoin(seats: number): boolean {
    return (
      (this.data.status === 'OPEN' || this.data.status === 'MATCHED') &&
      this.data.occupiedSeats + seats <= this.data.capacity
    );
  }

  canAccept(vehicleCapacity: number): boolean {
    return this.data.status === 'OPEN' && vehicleCapacity >= this.data.occupiedSeats;
  }
}

// pools/domain/PoolStateMachine.ts
const TRANSITIONS: Record<PoolStatus, PoolAction[]> = {
  OPEN:           ['accept', 'cancel'],
  MATCHED:        ['arrive', 'cancel'],
  DRIVER_ARRIVED: ['start'],
  STARTED:        ['complete'],
  COMPLETED:      [],
  CANCELLED:      [],
};

export function assertValidTransition(from: PoolStatus, action: PoolAction): void {
  if (!TRANSITIONS[from].includes(action)) {
    throw new InvalidTransitionError(from, action);
  }
}

// pools/domain/FareCalculator.ts
export class FareCalculator {
  constructor(private readonly config: FareConfig) {}

  computePoolTotal(tripDistanceM: number): number { /* integer paisa */ }
  splitFares(members: Member[], poolTotal: number): Map<string, number> { /* largest-remainder */ }
}
```

## Module Wiring Pattern (`*.module.ts`)

Each module's `*.module.ts` file is the **only** place where `new` is called for service classes. It exports the Express Router.

```ts
// rides/rides.module.ts
import { db } from '../../db/client';
import { RidesRepository } from './rides.repository';
import { RidesService } from './rides.service';
import { RidesController } from './rides.controller';
import { createRidesRouter } from './rides.routes';

const ridesRepository = new RidesRepository(db);
const ridesService    = new RidesService(ridesRepository, /* poolsService injected from pools.module */);
const ridesController = new RidesController(ridesService);

export const ridesRouter = createRidesRouter(ridesController);
```

`app.ts` imports only the exported routers and mounts them:

```ts
app.use('/api/auth',   authRouter);
app.use('/api/rides',  ridesRouter);
app.use('/api/driver', driverRouter);
// …
```

## Validation Flow

```
POST /rides
  ↓  authenticate         (shared/middleware/authenticate.ts)
  ↓  authorize('PASSENGER') (shared/middleware/authorize.ts)
  ↓  validate(createRideSchema) (shared/middleware/validate.ts → Zod safeParse → 400 on failure)
  ↓  RidesController.requestRide   (receives typed, validated body — no Zod here)
  ↓  RidesService.requestRide      (business rules: route served? pool has capacity?)
  ↓  RidesRepository / PoolsService
```

**Boundary rule:** Zod validates *request shape* at the HTTP boundary. Business invariants (route served, capacity, state legality) live in the service or domain object.

## File Naming Conventions

| Pattern | Example |
|---|---|
| Module files | `<domain>.<role>.ts` — `rides.service.ts`, `pools.repository.ts` |
| Domain classes | PascalCase, one class per file — `FareCalculator.ts`, `Pool.ts` |
| Shared infrastructure | camelCase — `authenticate.ts`, `errorHandler.ts` |
| Schema files (Zod) | `<domain>.schema.ts` — named exports like `createRideSchema` |
| Type files | `<domain>.types.ts` — local interfaces and enums |
| Module wiring | `<domain>.module.ts` — exports the Express Router |
| Tests | `<ClassName>.test.ts` or `<domain>.service.test.ts` |

## What Lives Where — Quick Reference

| Need | File |
|---|---|
| Add a new endpoint | `<domain>.routes.ts` |
| Add HTTP response shaping | `<domain>.controller.ts` |
| Add business logic / invariant | `<domain>.service.ts` |
| Add a DB query | `<domain>.repository.ts` |
| Add domain behaviour to an entity | `domain/<Entity>.ts` |
| Add a new table | `db/schema/<domain>.ts` + run `drizzle-kit generate` |
| Add a request DTO | `<domain>.schema.ts` |
| Add a shared error type | `shared/errors/<ErrorName>.ts` |
| Add a new third-party wrapper | `shared/wrappers/<tool>.ts` |
| Wire a new module | `<domain>.module.ts` → import router in `app.ts` |
